# 库存与库龄分析

用于日报的当前 FBA 库存章节。请求示例、响应拆包与通用格式见 [MCP 速查](mcp-quickstart.md)，展示结构见 [日报模板](report-template.md)。库存查询不使用报告日期；所有风险均标明查询时刻，不据此推断历史断货原因。

## 查询范围与完整性

- 默认每个已确认站点查询 `fulfillment=AFN`、`del=N`、`groupByField=SKU`，不限制商品在售状态和库存健康状态。未删除的停售商品也可能有积压。范围变化必须体现在标题和数据说明中。
- 按 `pageSize=100`、`orderField=sellerSku`、`orderFlag=1` 顺序翻页，后续页复用相同筛选和字段，可关闭 `includeFieldMeta`。记录查询时间范围、预期记录数、实际获取数及页码；完整覆盖确认后才生成全范围明细统计和风险排名。
- 优先用站点加库存记录 `id` 去重；缺少 `id` 时用店铺、站点、SKU、FNSKU 和配送方式识别重复。不能把同 SKU 的不同库存记录随意丢弃。空页提前出现、重复页或总数变化时有限重试，仍不一致则标记“库存明细覆盖不完整”，保留已获取数据，不无限翻页。
- 一次完整扫描同时支持库存概览、健康状态计数、补货清单、库龄统计和销售 Top5 关联。不要再为每个 SKU 重查，也不要把销售 Top5 当库存扫描范围。
- `inventoryStatistics` 是本次筛选范围汇总，每页可能重复返回，不能把各页汇总累加；保留一次可信结果及其查询时刻。分页失败时可独立保留该汇总，但标明哪些明细统计缺失。
- `ps.totalCount` 是记录数，不直接当作 SKU 数。按店铺、站点、SKU 计数；同 SKU 多记录状态不一致时标记待核实，不重复计入互斥状态。无法唯一识别记录或记录冲突时不能宣称覆盖完整。
- 站点分别展示；同币种也不能直接把多站点库存相加，共享库存可能重复。`shareInventory` 为真或共享关系不明时不生成跨站点库存总量。汇总金额的币种缺失，仅在该站点完整明细的币种明确一致时继承，否则标“币种未确认”。

## 库存概览与字段

- `supplyInstock`：当前 FBA 可售数量；`supplyInbound`：FBA 在途或入库中数量；`supplyReserved`：预留数量；`supplyUnavailable`：不可售数量；`supplyTotal`：接口库存总量。不能自行把各库存列相加重建总量，调拨与预留等口径可能重叠。
- `stockValue`：预估货值，展示为“预估库存货值”，不把它等同于会计成本或高库龄货值。优先使用同范围汇总；汇总缺失时，只有完整、无重复且对应字段齐全的明细才能求和，并标“明细汇总”。
- 库存健康状态：`0D` 尽快补货、`1W` 密切关注、`2N` 库存充足、`7S` 滞销、`8U` 未知、`9I` 已忽略。统计前两类和滞销 SKU 数，并单列未知／已忽略的覆盖数量；未返回状态也不能计入正常。“状态待核实”是额外备注，可与这些状态重叠，不能相加为总 SKU 数。
- FBA 范围为空且完整查询成功时写“所选范围没有 FBA 库存记录”。FBA 库龄不适用于 FBM；用户要求 FBM、本地仓、AWD 时另查另列，字段缺失标“—”，不沿用 FBA 字段含义。

## 补货风险与销售关联

- `salesVelocity` 是系统加权日均销量；`estimateSaleDays` 是当前可售库存预计可售天数，`estimateSaleDaysTotal` 是计入在途等库存后的预计可售天数，二者分别展示。`preparationDays` 已包含采购、运输和安全库存等备货天数，不重复加安全天数。
- 优先使用系统可售天数，仅接受非负有限数值；用于覆盖判断的备货周期需大于0。日均销量为0时显示“无动销，无法估算”，不将接口的0天理解为立即断货；天数缺失时保留“—”，不随意改用另一窗口销量补算。
- 风险候选包括系统 `0D/1W`；另将同时满足“在售、有效日均销量大于0、可售库存为0或有效可售天数短于有效备货周期”的商品列为“需核查覆盖缺口”，不要改写系统状态。停售、未知或已忽略状态不能仅因可售数量为0而要求补货。
- 清单优先显示在售且有动销的可售库存为0商品，再显示系统“尽快补货”、其余覆盖缺口与“密切关注”；同类有效可售天数由短到长，缺失值放后。停售、未知或已忽略但存在明确风险信号时保留为“状态待核实”，不伪装正常。
- `purchaseQuantity/purchaseDate` 和 `toFBAQuantity/toFBAQuantityDate` 分别是系统建议采购量／日期、建议发 FBA 量／日期。只展示实际返回的建议，不自行推导采购数量或承诺到货；缺失与真实0分别展示。日期已过去可写“建议日期已过，核查是否已处理”，不能断言用户未采购。
- 含在途可售天数长，不代表在途一定在断货前到仓。缺少到货时间时建议核查到货安排；不据此消除风险，也不自动建议停广告、调价或下采购单。
- 销售 Top5 按 `(sellerId, marketplace, sellerSku)` 关联库存，不能只按 SKU 文本或 ASIN 跨店匹配。单站点查询可用请求范围补充缺失的店铺／站点身份；同键多条库存无法确认归并语义时标“多记录待核实”，不相加可售天数、日均销量或建议采购量。
- Top5 的当前可售天数标为当前库存参考；FBA 扫描未覆盖的 FBM 商品标“不适用（FBM）”，未知配送方式或未匹配商品标“未匹配”，不能补0。除非两期销量已单独验证，否则只能说“近7天销售额较高”，不能说“销量上涨”。

## 库龄计算

只使用以下七个互不重叠的分段，单位为件：

| 展示分段 | 返回字段 |
| --- | --- |
| 0–30天 | `inventoryAge0To30Days` |
| 31–60天 | `inventoryAge31To60Days` |
| 61–90天 | `inventoryAge61To90Days` |
| 91–180天 | `inventoryAge91To180Days` |
| 181–270天 | `inventoryAge181To270Days` |
| 271–365天 | `inventoryAge271To365Days` |
| 超过365天 | `inventoryAge365PlusDays` |

- `inventoryAge271To330Days` 已被271–365天覆盖，不能再加一次，也不能拿它代替缺失的271–365天。零保留；空值、负数、非整数或缺字段视为该项不可用，不补0。
- 库龄库存总量 = 七段之和；超过180天数量 = 181–270天 + 271–365天 + 超过365天。超过365天是超过180天的子集，两项风险数量不能再次相加。
- 每段占比、超过180天占比及超过365天占比的分母均为**同范围七段库龄库存总量**，不是 `supplyTotal` 或 `supplyInstock`。库龄库存与接口总库存可能不同，不强行对平；占比描述写“占有库龄记录的库存”。
- 全范围七段数量与占比需要完整分页及对应有效字段；任何记录缺少某段时该段合计标“—”，不输出残缺合计。超过180天数量需要末三段全部有效；占比还要求七段全部有效且分母大于0。只有末三段完整时可展示数量，但占比仍为“—”。
- 部分分页或字段缺失时，仍可展示已获取商品的有效库龄数量和清单，标题写“已获取范围／部分库龄数据”，附已获取记录数及缺项。不能称全范围分布、全店 Top5 或因没有命中而称无积压。空范围或分母为0时占比显示“—”。

## 高库龄与滞销清单

- 候选为超过180天数量大于0、超过365天数量大于0，或系统标为滞销的有库存商品；库龄字段缺失但滞销状态有效的商品可以保留，不能编造其库龄。补货状态未知／已忽略的商品也不能从库龄扫描中排除。
- 优先显示“有高库龄且系统滞销或近30天销量为0”的商品，再显示其余超过365天商品、其余超过180天商品、其余系统滞销商品；同组按有效超过365天数量、超过180天数量依次降序，缺失值排后。标题称“优先关注”，不是单一库龄字段的排行榜。
- `salesUnits7d/salesUnits30d` 是库存快照附带的近期销量，不假定等同于报告日截止的7天／30天窗口。近30天销量为0可写“近30天无销量”，缺失不能写0；未提供同期对比或用户阈值时，不主观判定“销量下降”“低销量”。
- 高库龄仍有持续动销时写“高库龄，结合动销评估消化”，不一概判断滞销。可建议核查售卖状态、促销毛利空间或去库存方案，但不自动执行促销、降价、移除或弃置。
- 库龄数量不等于仓储收费记录；不据此估算实际长期仓储费，也不把180天定义为统一收费起点。用户明确要实际费用时另用 `query_products(view.dataset=longTermStorageFees)`，注明费用期间与当前快照不同。
