# SellerSpace 亚马逊店铺经营日报

## 依赖与范围

- 数据来自当前宿主提供的 SellerSpace MCP，只使用店铺发现、能力/字段检索、经营与库存查询能力。日报中的采购、发货、去库存及广告建议仅供决策，不执行写操作。
- 先识别当前可调用工具中的 `get_stores`、`query_store_performance`、`query_products`、`query_inventory`、`query_ads` 能力，实际名称与前缀以宿主提供的工具为准。已直接提供业务工具时按各自 Schema 调用，不额外包裹 `toolName/arguments`。
- 工具未加载且宿主提供工具搜索时，搜索“SellerSpace 优麦云 店铺经营”；没有工具搜索不代表 MCP 不可用。只有环境实际提供检索/执行门面时才按该门面 Schema 转发；不要求固定的状态工具或 `providers.access` 字段。
- 若无法找到任何相关业务能力，停止并说明缺少 SellerSpace MCP；若查询返回授权失败，说明实际错误。不得以网页或本地凭据直连替代 MCP。
- 查询前阅读 [MCP 速查](references/mcp-quickstart.md)；库存分页、库龄计算和风险判断见 [库存与库龄分析](references/inventory-analysis.md)，包含库存章节时阅读。正文按 [日报模板](references/report-template.md) 组装。

## 1. 确定日报范围

- 复用当前对话已经确认的店铺/站点；需要发现或校验候选时调用 `get_stores`。未指定范围则展示候选并请用户选择，不自动遍历所有店铺。
- 从授权站点取 `marketplace`（如 US/DE，不能用 Amazon marketplaceId）、`timezone`，结合 `sellerId` 构造范围。
- 默认生成站点当地**昨日**日报，并附截至报告日的近7个完整日；用户指定历史日期或时间段时遵从指定范围。今日实时只在用户要求时增加，注明站点时间与“截至查询时刻”。
- 默认另附**截至查询时刻的 FBA 库存**，包含未删除的在售和停售商品，避免漏掉停售积压；不把它称为全店所有仓库库存。FBM、本地仓或 AWD 仅在用户要求且数据可用时单列。用户限定章节或库存范围时遵从其要求。
- 销售窗口与库存快照分别标注；历史日报中的当前库存仅作当前运营参考，不能解释历史销量变化。无同范围历史快照时，不生成库存环比、库龄趋势或历史库存值。
- 先固定报告日期和查询窗口，再发请求。近7天与前7天必须等长、不重叠；使用自定义日期确保商品、广告、店铺汇总窗口一致。不能将用户本地的“昨天”直接当作所有站点的昨天。
- 多站点按各自日期、时区和币种展示。相同窗口的店铺/商品查询可合并 `scope.stations`；广告按站点顺序查询，禁止跨店并行。跨币种金额不得相加或混排 Top5；没有确认统一展示币种时优先分站点查询和展示。

## 2. 查询经营数据

具体可执行参数及数据路径见 MCP 速查。查询计划只覆盖本次需要的章节：

1. **店铺表现**：查询报告日与近7天，使用 `view.dimension="market"`、`view.chainType="DAILY"`。需要环比时，只有确认返回的对比数据属于目标前日/前7天后才复用；无法确认或未返回时，分别查询对应的自定义前日/前7天窗口。
2. **逐日趋势与商品 Top5**：`query_products` 使用 `view={groupBy:"SKU",summary:"DAILY"}`，明确传 `sort={field:"revenue",direction:"desc"}`、`page={number:1,size:5}`。趋势取全范围汇总的 `summary.dateDims`，Top5 取 `pg.items`，不能用这5个商品凑全店趋势或总额。若接口未提供可确认的全范围逐日汇总，则注明趋势缺失。
3. **当前库存与库龄**：按库存分析规则调用 `query_inventory`，默认逐站点查询 FBA，以 SKU 分组完整分页；从同一份库存数据生成概览、补货风险和库龄清单。库存扫描独立于销售 Top5，不能只给畅销商品查库存。用已获取的库存按店铺、站点、SKU 关联销售 Top5，减少重复查询。当前库存不得改走 `query_products`。
4. **广告表现**：先通过 `discover_capabilities({adsEntity:"campaign"})` 获取契约（若已加载完整契约则复用），逐站点查询 `query_ads(entity="campaign")`。按 `cost` 服务端倒序取5个活动，显式选择 `campaignStatus="notArchived"`，汇总和活动标题均注明“未归档活动”；不能将其称为全账户广告总计。
5. **今日实时**：仅在需要时查询 `query_store_performance(period.preset="TD")`，不与完整一天做同口径增长比较。

分别记录各部分的实际范围、币种、成功/失败/无数据状态。失败不等于零，缺少库存、广告或图表时仍可交付已获取的日报，并在开头标注缺项；报告日核心数据不可用时，明确交付为“不完整日报”。库存分页不完整时保留可信汇总，明细只标“已获取范围”，不能据此声称全站点无风险。参数错误先按 Schema 修正，限流/短暂错误按返回提示有限重试，持续失败则保留错误原因，不无限重查。

## 3. 组装与解释

- 按 MCP 速查先拆响应包装，再按日报模板取字段；不要把 `data.data`、`summary.chainSummary` 等路径当成普通指标。
- 保留原始返回值，展示时再格式化。空值显示“—”，真实零保留；百分比、金额、倍数分别处理，规则只维护在 MCP 速查中。
- 展示顺序为：**核心结论 → 优先处理事项 → 报告日表现 → 当前库存与库龄 → 近7天汇总和趋势图 → 商品 Top5 → 广告明细 → 逐日明细与数据说明**。让待办与库存风险出现在长表之前；用户指定顺序时优先遵从。
- 结论写2～4条有数字支持的变化或风险；优先处理事项列至多3项，每项写明对象、依据、建议及时间性质（报告日问题或当前库存问题）。按紧迫性和经营影响排序，后面的明细不重复长篇结论。
- 报告中标注真实覆盖范围：全店经营汇总、FBA 库存快照、商品 Top5、未归档广告活动汇总。不同来源口径不一致时说明差异，不强行补齐或对平。
- 异常可包括负利润、完整报告日零销量、系统补货提醒及高库龄伴随滞销；ACoS 超目标仅在已有用户目标时判定。补货优先采用系统状态与实际备货周期，不编造统一安全天数；高库龄不自动等于滞销。不能把 Top5 或部分库存中的现象推广为全店，也不能由同步缺失断言零销量。

## 4. 生成趋势图

- 将核对过的逐日数据按日期升序传给 `scripts/chart.mjs`；日期与每条序列一一对应，缺失日期保留标签并传 `null`，不补零。图表与明细表使用同一份数据。
- 输入格式见脚本头部；金额图必须传该组数据的 `currency`。销售额与广告花费同图，订单数自动独立成图；每个币种分别生成文件。
- 命令：`node <skill-dir>/scripts/chart.mjs <input.json> <output.svg> [<output.png>]`。SVG 生成不依赖第三方库；可选 PNG 转换使用 macOS 的 `qlmanage`，最长等待30秒。
- PNG 不可用时交付 SVG 链接与逐日表；脚本不可用或数据不符合输入要求时保留逐日表，不阻塞日报。

## 5. 校验后交付

- 核对核心金额、订单、利润、ACoS 与原始返回值；确认环比日期与计算、币种、Top5 排序和数据覆盖说明准确。
- 核对库存分页覆盖、SKU 关联、快照时间和 FBA 范围；库龄采用不重叠分段，占比分母为同范围库龄库存，不把在途或重叠库龄重复相加。采购、发货建议标明系统来源，空值和零销量的可售天数按库存规则处理。
- 检查趋势图与逐日表的日期、数值、缺失点一致，生成的本地文件确实存在。
- 在当前对话直接交付日报正文。结论和待办用短句，数值比较用紧凑表格，风险清单默认各展示5个，完整扫描不等于全文铺开所有 SKU；具体排版见模板。用户要求不用表格时改用同结构列表。提供图表的可访问链接或图片，文件引用使用绝对路径。
- 用户要求保存文件时将同一份正文保存为 Markdown 并给出链接；不重复生成不同数字的“精简版”。数据说明包含站点时区、具体窗口、币种、生成时间、库存覆盖与缺项及优麦云同步限制。
