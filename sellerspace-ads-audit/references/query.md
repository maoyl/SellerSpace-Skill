# SellerSpace Ads Audit Direct API Contract

The bundled CLI calls the SellerSpace read-only analysis APIs directly with `X-API-Key`. It never sends JSON-RPC `tools/call` requests to MCP. Business values are preserved; credential-like fields are recursively removed. To prevent agents from guessing through the backend's nested envelope, only `query_ads` is structurally normalized.

## Actual endpoints

- `get_stores`: `GET /api/mcp/analysis/stores`
- `query_store_performance`: `GET /api/mcp/analysis/website`
- `query_ads` (campaign): `POST /api/mcp/analysis/cpc/campaigns/page`
- `query_ads` (adGroup): `POST /api/mcp/analysis/cpc/adGroups/page`
- `query_ads` (productAds): `POST /api/mcp/analysis/cpc/product_ads/page`
- `query_ads` (keywords): `POST /api/mcp/analysis/cpc/keywords/page`
- `query_ads` (targets): `POST /api/mcp/analysis/cpc/targets/page`
- `query_ads` (searchQuery): `POST /api/mcp/analysis/cpc/keywords_query/page`
- `get_metric_history` (time): `GET /api/mcp/analysis/cpc/common/metric/analysis`
- `get_metric_history` (placement): `GET /api/mcp/analysis/cpc/common/placement`
- `get_metric_history` (hourly): `GET /api/mcp/analysis/cpc/campaigns/analysis/hourly-stream`

Only these compiled-in endpoints are allowed. Callers cannot supply a URL, path, HTTP method, or status filter.

## get_stores

Input: `{}`. The direct `GET` response is returned without business-field projection. Credential-like fields such as authorization tokens are recursively removed.

## Deterministic audit command

After the user explicitly selects one returned store + marketplace station and supplies target ACoS, run `node <skill-dir>/scripts/sellerspace-cli.mjs audit` with one JSON object on stdin.

Required input: `sellerId`, `marketplace`, `storeShortNameAndMarketplace`, and `targetAcos`. Build `storeShortNameAndMarketplace` as `<selected sellerId>-<selected marketplace>` from the exact chosen combination returned by `get_stores`. Optional: `storeName`, `dateType`, `fromDateStr`, `toDateStr`, `adType`, and the selected station's IANA `timezone`. Target ACoS accepts ratio, number-percent, or percent text such as `0.3`, `30`, or `30%`.

The command is a local read-only orchestrator, not a SellerSpace operation. It uses only the endpoint whitelist above, retries one explicit rate-limit response once when the instructed delay is at most 60 seconds (otherwise it fails closed), fetches all enabled Campaigns, reaches 90% spend coverage for the five child entities, builds canonical cross-context indexes, and performs evidence-selected Campaign DAILY/placement drilldowns with bounded concurrency.

Its single JSON result contains `accountSummary`, `thresholds`, `ratings`, `recommendations`, `observations`, `dataPreview`, `trendEvidence`, `coverage`, and `auditMeta`. Recommendations are generated by the bundled deterministic engine. The agent may explain or rank them but must not invent an action outside `recommendations`, replace the user target, or prescribe exact bid/budget percentages.

`dataPreview` contains at most five presentation rows per entity while the engine analyzes every fetched row. This is a chat presentation limit, not a query, Campaign, or evidence limit.

## query_store_performance

Required input: `storeShortNameAndMarketplaces` (for example `["9614-US"]`). Optional: `dateType`, `fromDateStr`, `toDateStr`, `currencyCode`, `chainType`, `dimension`.

Defaults: `dateType=NM`, `chainType=HOURLY`, `dimension=market`. `dateType=CU` requires both date strings.

## query_ads

Required input: `entity`, `sellerId`, `marketplace`. Supported entities: `campaign`, `adGroup`, `productAds`, `keywords`, `targets`, `searchQuery`.

Optional input: `dateType`, `fromDateStr`, `toDateStr`, `adType`, `campaignId`, `adGroupId`, `page`, `pageSize`, `orderByField`, `orderType`.

The CLI always sends exact enabled-state filters and rejects caller-supplied status fields:

- `campaign`: `campaignStatus=enabled`.
- `adGroup`: `campaignStatus=enabled`, `adGroupStatus=enabled`.
- `productAds`, `keywords`, `targets`: `campaignStatus=enabled`, `adGroupStatus=enabled`, `status=enabled`.
- `searchQuery`: `campaignStatus=enabled`, `adGroupStatus=enabled` (search terms have no leaf state).

Defaults: `dateType=NM`, `page=1`, `pageSize=100`, `orderByField=cost`, `orderType=2`. Page size cannot exceed the backend maximum of 100.

The CLI validates the real backend shape `response.data.list.items` and returns one unambiguous structure:

- aggregate metrics: `data.summary`
- fetched rows: `data.page.items`
- backend total: `data.page.totalCount`
- pagination: `data.page.currentPage` and `data.page.pageCount`

Envelope metadata and non-list business fields remain under `data`. The old nested paths `data.data` and `data.list` do not exist in the CLI result. Missing or malformed pagination fields fail with `INVALID_RESPONSE`; never infer counts from another path.

### Canonical row identity

Every `data.page.items[]` row preserves all raw SellerSpace fields and adds a CLI-owned `canonical` object. Use `canonical` for identity, labels, joins, recommendation targets, and metric-history calls; do not guess a raw field name or substitute one entity's text for another.

Common canonical fields are `entity`, `entityId`, `entityName`, `campaignId`, `campaignName`, `adGroupId`, `adGroupName`, `historyAdDataType`, and `historyId`. Entity-specific mappings are fixed:

- `campaign`: `entityId/historyId <- campaignId`; `entityName <- campaignName`; history type `campaign`.
- `adGroup`: `entityId/historyId <- adGroupId`; `entityName <- adGroupName`; history type `adGroup`.
- `productAds`: `entityId/historyId <- adId`; `entityName <- productTitle`, then `asin`, then `sellerSku`; exposes `asin` and `sellerSku`; history type `productAd`.
- `keywords`: `keywordText <- keywordsText`, falling back to legacy `keywordText`; `keywordMatchType <- keywordsMatchType`, then `matchType`, then `matchTypeStr`; `entityId/historyId <- keywordId`; history type `keyword`.
- `targets`: `targetExpression <- targetExpression`, then `resolvedExpression`, then `targetValue`; `targetType <- originalTargetType`, then `targetType`, then `expressionType`; `entityId/historyId <- targetId`; history type `target`.
- `searchQuery`: `searchTermText <- query` only. `sourceKeywordText` and `sourceKeywordMatchType` describe the originating keyword and must never replace the search term. `queryIsAsin` is normalized to `Y/N`. `historyId` is the backend-compatible composite of `query + keywordId + targetId`, and the history type is `searchTerm`.

A canonical field can be `null` when SellerSpace did not return the required raw identity. Do not fabricate it. In particular, an empty `canonical.searchTermText` means the search-term row cannot be named or safely acted on; an empty `canonical.historyId` means no metric-history request is allowed.

## get_metric_history

Required input: `sellerId`, `marketplace`, `adDataType`, `id`, `fromDateStr`, `toDateStr`. Optional: `dimension`, `timeType`, `placementBusiness`, `dateType`.

- Normal time history calls `common/metric/analysis`.
- DAILY history supports `campaign`, `adGroup`, `productAd`, `keyword`, `target`, and `searchTerm`. Pass the row's exact `canonical.historyAdDataType` and `canonical.historyId`; never substitute Campaign history for missing leaf history or construct an ID by guesswork.
- `timeType=HOURLY` calls `campaigns/analysis/hourly-stream` and maps the entity to the backend `type` exactly.
- `dimension=placement` supports `campaign`, `productAd`, `keyword`, and `target`; it calls `common/placement` and maps the exact returned entity ID to `campaignId`, `adId`, or `keywordId`. Never use Campaign placement rows as leaf-entity evidence.

## Audit rules

- After preflight, call `get_stores` only to present valid store + marketplace combinations. Require the user to explicitly select exactly one returned station and provide its target ACoS before calling any performance, ads, history, or placement endpoint. Never auto-select even a sole station, and never derive target ACoS from account averages or suggestions.
- The current audit workflow is chat-only. Do not offer HTML, ask about HTML, build report JSON, or invoke the bundled legacy renderer.
- After station and target confirmation, use the deterministic `audit` command instead of manually planning pagination, joins, thresholds, histories, or recommendations through repeated `call` commands.
- Default audit period is `dateType=NM` (rolling 30 days), never `LM`.
- Fetch every enabled Campaign page. For the other five core entities, paginate cost descending until fetched unique rows cover at least 90% of the positive summary cost or the final page is reached.
- Build normalized cross-context indexes for search terms, ASINs, keywords, and targets before selecting actions. Select Campaign drilldowns from sufficiently sampled P1/P2/P3 evidence and query exact-entity DAILY history when a leaf recommendation depends on persistence. There is no Campaign, entity-history, placement, or business-call count cap.
- The Skill never calls write, export, browser, or MCP JSON-RPC operations.
